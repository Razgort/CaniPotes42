# 02.1 Event Creation / Edit — Proposition [S] Suggest (Freya)

**Statut :** **Validé** — décisions intégrées dans `02.1-event-creation-edit.md` ([P] Specify).  
**Scénario :** Perrine's Admin Day  
**Date :** 2026-03-22  

### Décisions Leader (retenues)

1. **Brouillon / Publié :** un bouton **« Enregistrer »** + **toggle** (pas deux boutons séparés).  
2. **Modale :** **Oui MVP** à la transition vers **Publié** (confirmation avant envoi API).  
3. **Carte :** affichée **en haut** sur mobile **si** « Afficher la carte GPS pour cet événement » est activé ; sinon bloc carte masqué — cas **CNEAC / lieu fixe**. Défaut pour les **nouveaux** événements : paramètre club `defaultEventShowMap`, sinon carte **activée**.

---

## Step 08 — Page context

- **Tenant :** Club actif (`activeClub`) — tout est scoped `club_id`.  
- **Rôle requis :** `ADMIN` ou `OWNER` (création / édition).  
- **Mode :** Création (nouvel événement) ou **Édition** (même écran, données préremplies).  
- **Plateforme :** Mobile-first ; carte et champs utilisables au pouce ; desktop = colonne formulaire + carte plus large.

---

## Step 09 — Page name

- **FR :** « Nouvel événement » / « Modifier l’événement »  
- **Route (proposée) :** `/clubs/:clubId/events/new`, `/clubs/:clubId/events/:eventId/edit`  
- **Slug fichier :** `02.1-event-creation-edit` _(inchangé)_

---

## Step 10 — Page purpose

Publier (ou mettre à jour) une séance avec **titre, horaire, lieu texte + pin GPS fiable**, visibilité brouillon/publié, et capacité optionnelle — le tout en **< 90 s** pour le chemin heureux (Trigger Map).

---

## Step 11 — Entry points

1. **Feed admin / CTA** : « Créer un événement » depuis l’accueil club ou liste événements.  
2. **Deep link** : édition depuis fiche événement existante (icône crayon).  
3. **Retour arrière** : après sauvegarde brouillon, retour liste sans perdre le brouillon.

---

## Step 12 — Mental state (Q4 scenario)

- **Espoir :** « Je pose le pin, je publie, les membres voient la bonne carte. »  
- **Peur :** « Pin au mauvais endroit / carte vide / je perds ce que j’ai saisi. »  

→ L’UI doit **montrer la carte en permanence** (split ou stack avec aperçu clair) + **autosave brouillon** ou confirmation avant quitter si changements non sauvegardés.

---

## Step 13 — Desired outcome

- **Utilisateur :** Événement enregistré (brouillon ou publié) avec pin validé visuellement.  
- **Business :** Zéro incident « carte cassée » ; admin autonome sans formation.

---

## Step 14 — Variants

| Variant | Description |
|---------|-------------|
| **A — Create** | Champs vides, carte centrée sur dernière position club ou siège du club |
| **B — Edit** | Champs préremplis, même layout ; bandeau discret « Modification » |
| **C — Draft** | Toggle ou bouton « Enregistrer brouillon » vs « Publier » ; état visible dans l’en-tête |
| **D — Publish confirm** | Modale légère optionnelle : « Publier maintenant ? Les membres seront notifiés. » _(si notifications MVP)_ |

---

## Step 15 — Structure écran (proposition haute fidélité conceptuelle)

### Layout mobile (scroll vertical)

1. **Header**  
   - Retour (←)  
   - Titre dynamique : « Nouvel événement » / « Modifier »  
   - Action secondaire : menu `⋯` (dupliquer / supprimer en édition — V2 si besoin)

2. **Bloc Carte** (hauteur min ~220px, expandable plein écran)  
   - Carte interactive (Mapbox / Leaflet / Google — **décision tech Open Questions**)  
   - Pin draggable + recherche adresse (champ au-dessus ou overlay)  
   - Lien « Centrer sur ma position » (permission GPS navigateur)

3. **Bloc Formulaire** (sections avec `gap-4`)  
   - **Titre** — requis, max 120 car.  
   - **Date & heure début** — date picker + time ; fin optionnelle ou durée.  
   - **Lieu (texte libre)** — requis pour accessibilité hors ligne.  
   - **Description** — textarea, optionnel, markdown léger V2.  
   - **Capacité max** — nombre optionnel.  
   - **Visibilité** — segment control : `Brouillon` | `Publié` _(libellés FR)_

4. **Barre d’actions fixe (bas)**  
   - `outline` : « Enregistrer brouillon »  
   - `primary` : « Publier » _(désactivé si validation KO)_  

### Layout desktop (≥1024px)

- Deux colonnes : **gauche 40 %** formulaire, **droite 60 %** carte fixe sticky dans le viewport.  
- Même barre d’actions en bas du formulaire ou footer sticky.
